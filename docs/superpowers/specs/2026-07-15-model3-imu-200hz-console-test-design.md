# 模型3 IMU 200 Hz 控制台测试设计

## 目标

在不启动视觉识别和 UART 的情况下，单独运行模型3现有 `ImuAttitude` 模块，
验证 MaixCAM2 能否按 5 ms 周期持续完成 IMU 读取、Mahony 姿态解算和控制台
输出。

本测试不执行陀螺仪校准，只加载独立校准 App 已保存的
`model3_gimbal` 校准参数。最终视觉与 IMU 的 200 Hz 合帧发送不属于本次修改。

## 文件与职责

新增 `模型3/imu_attitude_test.py` 作为独立测试入口：

- 创建并启动现有 `ImuAttitude`，不复制 IMU 初始化或姿态算法。
- 找不到 `model3_gimbal` 时打印明确提示并退出，不自动校准。
- 使用 `time.ticks_us()` 和绝对截止时间按 5000 us 调度。
- 每个周期调用一次 `sample()`，打印序号、Yaw/Pitch 角速度、Yaw/Pitch 角度和
  有效位。
- 每秒打印实际采样频率、实际打印频率和累计跳过周期数。
- 通过 `app.need_exit()` 正常响应 MaixVision 停止操作。

`模型3/imu_attitude.py`、`模型3/find_circle.py`、`模型3/maixcam_link.py` 和
`模型3/main.py` 的运行职责及接口保持不变。

## 调度与统计

首个采样周期立即执行。每次采样和打印后，下一截止时间固定增加 5000 us，
不使用“当前时间加 5000 us”，避免单次执行耗时累积为长期频率误差。

如果采样、解算和打印已经超过一个或多个截止时间，测试程序跳过过期时隙，
将其计入 `skipped`，然后等待下一个仍在未来的截止时间。该统计用于区分：

- IMU 与姿态解算本身能够达到 200 Hz；
- 控制台输出阻塞导致无法保持 200 行/秒。

数据输出采用紧凑格式，降低字符串格式化和日志传输负担：

```text
imu[00123] yr=+1.2 pr=-0.4 ya=+12.35 pa=-2.10 flags=0x06
[rate] sample=199.8Hz print=199.8Hz skipped=0
```

## 异常处理

- 校准文件不存在：提示先运行独立校准 App，随后退出。
- IMU 初始化异常：打印异常并退出，避免产生看似有效的零数据。
- 单次读取或解算异常：累计错误计数并继续后续周期；错误信息只在首次及每
  200 次时打印，防止异常日志进一步破坏时序。
- `FLAG_ATTITUDE_VALID` 未置位时仍打印数据和标志，便于观察启动稳定过程，
  但不得把角度字段视为有效姿态。

## 测试与验收

### 主机侧自动测试

- 测试入口复用 `ImuAttitude`，不包含校准和 UART 调用。
- 校准缺失时不进入采样循环。
- 5 ms 绝对截止时间调度能按序采样，并正确统计跳过时隙。
- 输出字段正确还原 x10 角速度和 x100 角度。
- 现有模型3 IMU 与通信测试继续通过。

### MaixCAM2 上板验收

- 控制台连续输出约 200 行/秒。
- 每秒 `[rate]` 中 `sample` 和 `print` 接近 200 Hz。
- 静止运行至少 60 秒，IMU 异常数不增长。
- `skipped` 不持续快速增长；若持续增长，则说明控制台逐条打印不适合用于
  最终运行，但不能据此判定最终二进制 UART 200 Hz 合帧发送失败。
