# 模型3纯 Python 200 Hz反馈优化设计

## 目标

在保留模型3现有 Python 项目结构和28字节通信协议的前提下，使系统同时运行：

- 视觉识别与画面预览不低于30 FPS；
- 板载IMU按200 Hz目标节拍读取并完成姿态解算；
- UART4以460800 baud、8N1发送最新IMU和最近一次视觉快照；
- 发送频率和IMU采样频率在1秒统计窗口内稳定处于195～205 Hz；
- 连续运行60秒时，`imu_err` 和 `write_err` 不增长，`skipped` 增量不超过每秒5次。

视觉只有约30 FPS，因此同一组视觉误差允许被连续复用约6～7个UART帧。每个UART帧中的IMU字段必须来自该发送周期的新采样。

## 已知事实与约束

- 用户已上板验证IMU与姿态模块单独运行可达到约200 Hz。
- 用户已上板验证视觉模块单独运行可达到约30 FPS。
- 当前整合程序约70～78 Hz，且 `tx` 与 `imu` 相同，`skipped` 持续增长。
- 当前5 ms绝对截止时间调度保持不变，不使用“当前时间加5 ms”的累积漂移调度。
- 不更改28字节帧布局、字段含义、大小端和CRC-16/CCITT-FALSE协议。
- 不新增进程、C++扩展或新的业务模式。
- 保留现有 `main.py`、`find_circle.py`、`imu_attitude.py` 和 `maixcam_link.py` 的职责边界。
- 用户当前在 `模型3/find_circle.py` 和 `模型3/main.py` 中的未提交修改必须保留。

## UART4 460800可行性与边界

MaixCAM2官方文档给出的UART默认时钟为200 MHz、理论最高波特率为4 Mbit/s，但官方常见实测列表只明确列出115200。因此460800在分频上可行，仍必须以上板链路结果作为最终证据。

按官方分频公式，460800对应分频值约27.125，实际波特率约460829，误差约0.0064%。28字节8N1帧的物理占线时间约0.61 ms，200帧/秒占用约12.2%的UART带宽。

默认使用460800。如果出现短写、MSPM0持续CRC失败或帧同步丢失，先把波特率单独回退到230400做对照，不同时改动其他性能参数。

## 运行架构

### 视觉主循环

`模型3/main.py` 继续调用 `FindRectCircle.run()`，以约30 FPS产生视觉误差。只有 `updated=True` 时才调用 `publish_target()` 更新快照；未识别期间通信线程按照原有200 ms超时规则清除目标有效位。

性能运行时仅保留候选矩形框绘制，关闭误差文字、误差线和第三圆轮廓点绘制。每个视觉帧结束后主动让出约1 ms CPU时间，给200 Hz通信线程明确的调度机会。

程序启动时，如果当前Python运行时提供 `sys.setswitchinterval()`，将线程切换间隔设置为1 ms。若接口不存在则继续运行并打印一次明确提示，不因此退出。

### 200 Hz通信线程

`MaixCamLink._tx_worker()` 继续独占以下顺序：

1. 等待下一个绝对5 ms截止时间；
2. 读取一次IMU并完成一次Mahony姿态解算；
3. 读取最近一次视觉快照；
4. 生成28字节帧并计算CRC；
5. 向UART4写入完整帧；
6. 统计发送、错误、迟到和跳过周期。

不再拆出额外Python线程，避免增加锁、共享对象和解释器调度竞争。

## 性能优化

### CRC优化

保留 `crc16_ccitt_false(data)` 接口和标准结果，将每字节8次Python位循环改为256项查表算法。查找表在模块加载时生成一次，不在200 Hz循环中重复生成。

主机测试必须证明优化前后的标准向量和多组帧内容完全一致。

### 分配与组帧

保持 `struct.pack` 的固定二进制格式和返回 `bytes` 的现有接口，避免字符串协议和格式化输出进入高频路径。本轮不引入 `bytearray` 与 `pack_into()`，不为减少一次小对象分配承担MaixPy UART接口兼容性风险。

### 调度与显示

- Python线程切换间隔目标为1 ms；
- 视觉每帧完成后让出1 ms；
- 关闭误差文字、误差线和第三圆轮廓点；
- 保留矩形框，满足现场判断YOLO候选目标的需要；
- 状态只按1秒周期打印，不在200 Hz循环中逐帧打印。

## 性能诊断

通信线程增加低开销的累计计时，至少覆盖：

- 截止时间唤醒迟到量；
- IMU与姿态解算耗时；
- 组帧与CRC耗时；
- UART `write()` 调用耗时；
- 整轮总耗时。

计时结果只累计总值和最大值，由主线程每秒读取并打印一次。不得在通信线程中逐帧输出。性能统计不得改变既有 `get_stats()` 和 `get_imu_stats()` 返回契约，新增独立的只读统计接口。

## 错误处理

- IMU读取异常继续只累计并限频打印，不停止视觉循环；
- UART异常或短写继续累计 `write_err`，不得把失败帧伪装成成功；
- 视觉快照超时继续发送IMU有效帧，但清除目标有效位并将X/Y误差置零；
- 460800链路异常时使用230400做单变量对照，不自动静默降速；
- Python线程切换接口缺失时明确提示，并依靠分段计时判断是否仍满足验收。

## 测试与验收

### 主机自动测试

- CRC标准向量 `123456789 -> 0x29B1` 保持通过；
- 多组旧算法期望帧与新算法输出逐字节相同；
- `main.py` 配置UART4为460800；
- 性能模式关闭误差文字、误差线和第三圆轮廓点，并保留矩形框；
- 主线程存在明确的1 ms让出点；
- 新增计时统计不改变旧统计接口；
- 现有模型3测试全部继续通过。

### MaixCAM2与MSPM0上板验收

1. 先单独发送固定28字节测试帧，确认MSPM0在460800下持续接收、帧长和CRC正确；
2. 启动完整视觉、IMU和UART程序；
3. 静止运行至少60秒；
4. 记录每秒 `vision`、`tx`、`imu`、`imu_err`、`write_err`、`skipped` 和分段耗时；
5. 验收条件：视觉不低于30 FPS，`tx` 和 `imu` 处于195～205 Hz，错误数不增长，`skipped` 增量不超过每秒5次；
6. 让目标进入和离开画面，确认视觉有效位按200 ms超时规则变化，同时IMU字段持续更新。

如果达不到验收要求，根据分段耗时只修改占比最大的一个环节并重新测试，不同时叠加多个猜测性修改。
